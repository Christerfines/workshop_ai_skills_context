# The Map: What Lives Where, Not What It Says

> Text version of [`preparation/02-the-domain.md`](../02-the-domain.md) — same content, written as an article instead of a podcast script. ~4-minute read.

This is a repository map, deliberately not a content walkthrough: what each folder holds and what *kind* of question it answers — not the terms, numbers, or categories written inside any document. Reading the actual documents, and deciding what's relevant to a given case, is Exercise 2's job, not this article's.

That boundary is deliberate, not coyness. Knowing that a filing cabinet has five drawers, and roughly what each drawer holds, is completely different from having read every folder in advance. The first saves you time. The second would just be doing Exercise 2 for you before you've started it — and figuring out what's actually relevant, file by file, is a skill this workshop is built to teach, not a fact to hand you upfront.

Five folders, in order from smallest to biggest.

## `company/`

Two short files: background on NordicBike itself, and how to contact support. Useful for orientation, almost never something an eligibility decision actually hinges on. If you're trimming context for a warranty case, this is usually the first thing you can leave out entirely rather than excerpt.

## `products/`

One file per product line — full specifications: what the product is, how it's built, what's configurable. Every case is about some specific product, so you'll always touch one of these files — but only ever the one file that matches the product in the case you're looking at, plus usually only a fraction of what's in it.

## `policies/`

Four documents, and this is genuinely the ground truth for every decision your agent makes:

- One document covers product warranty coverage.
- One covers a completely different situation — a customer returning something they simply don't want anymore.
- One is pure logistics: shipping and turnaround, downstream of whatever eligibility decision already got made.
- One defines when a case needs to go to a human instead of being resolved automatically.

Four documents, four distinct jobs — worth knowing which job each one does before you're hunting through all four at once mid-case. Notice what's *not* here: not one number, not one category, not one rule — just, four documents exist, here's the kind of question each one answers. When you open them during the workshop, expect each to be organized internally too, usually with a clear structure you can skim before reading closely. That skimming habit is worth having going in; the content underneath it is not something to memorize in advance.

## `customers/` and `cases/`

Two more folders, paired. `customers/` holds one file per customer — contact details and purchase history, the record you check stated facts against rather than taking a customer's word for something you can verify. `cases/` holds the ten support tickets themselves — what the customer actually wrote in, which is where every exercise starts.

## The navigation habit worth having in advance

For any given case, you'll typically need to cross-reference the case file, the matching customer record, the matching product file, and some subset of the four policy documents. Which subset, and which parts of each — that's not something to know in advance. That's the actual exercise. What's worth knowing in advance is just that those are the categories you'll be reaching across, so you're not discovering the folder structure itself while the clock is running.

## If you remember exactly one thing

Five folders, five different jobs. Background, specs, rules, people, tickets. When a case lands in front of you, you already know which drawer to open for which kind of fact. Which page in that drawer, and whether it even matters for the case at hand, is a judgment call every single time — and it's the judgment call the rest of this workshop is built around.

That's also exactly why this article stops here rather than walking you through what the warranty document actually says. You're going to read it for real, against a real case, under a real budget, starting with the next topic. Better that the first time you engage with the actual content is the time it counts.
